## SG81 APK 中确认的内容

分析对象：SG81-Lab-1.2-md3.apk.1，包名 `com.sg81.lab`，内部版本 `1.2-live-details`。
APK SHA-256：`ba7b4e767d663c68c56f0393e1edf9792f325546bd6eef6f268521a3e098c7dd`。
内置 `sample.bin` 为 233472 字节，其 SHA-256 为
`883e26a421b0e364b425653ba980d55bf8f97e843ec3388195c674843fd4b96b`，与 APK 中声明值一致。

Java 界面校验样本后以普通权限启动原生 Worker。Worker 用 Unicorn 执行样本，把受支持的只读查询转发至本机。
其原生代码保留回放模式，但当前扫描入口不传回放目录，APK 中也未附带该模式的查询数据文件。

| 已确认机制 | 证据与结论边界 |
| --- | --- |
| 进程时钟、存活状态 | 样本存在时钟、pidfd、轮询调用，Worker 有对应处理。没有完整还原所有筛选分支，不能给出确定阈值或覆盖率。 |
| 进程路径与文件属性 | 样本和 Worker 均涉及文件属性、文件系统属性以及读取操作；不能把接口存在直接解释为某一种隐藏方案已被可靠识别。 |
| SELinux 与身份信息 | 存在安全属性读取、执行域字段、推导 UID。推导 UID 与真实读取的身份必须分开。 |
| 日志 | Worker 使用 liblog 读取自身权限范围内的数据；不代表拥有全设备日志权限。 |
| 候选详情 | Java 在扫描后读取进程名、状态、启动标记，再查询包名和应用名。前后启动标记不一致时丢弃所读元数据。 |
| 结果结构 | Java 将样本报告中的字段整理成候选列表。候选输出不能证明恶意行为；样本来源及原宿主的最终处置逻辑未经核验。 |

这是静态分析，未在 Android 真机执行。未将样本、回放数据或未验证的字段推断加入生产采集器。
gpu-check 已有进程时钟、pidfd、AVC 和路径观察机制；最新基线另有线程类型检查，二者不应仅凭名称视为同一套算法。

## 修复与行为变化

1. **GPU 全局活跃状态使用经校验的差值。** 原实现用原始无符号减法单独累计 `advancedSlots`，
   与 `slotDeltas` 的有效性策略不同。新出现的槽、过大跳变或无效时间间隔可出现一边为 `null`、另一边仍标活跃的矛盾。
   本次统一数据来源；合法的有界计数回绕仍被接受。新增 `activityKnown`、`comparableSlots` 和 `activityBasis`，
   没有可比较差值时显示未知，并中断 AVC 组合规则的 GPU 连续计数。
2. **显示与证据强度一致。** 生命周期命中显示“GPU 活动时序吻合 · 归属待核实”；名称命中显示“可疑图层名称 · 待核实”。
   两类间接线索用黄色显示，保留原有检测条件及原始证据。进程卡片不再删除“按进程 GPU 归属未确认”的提示。
3. **完整快照导出。** 用户可将当前 JSON 保存到系统文件选择器指定的位置，包含 CPU 前十以外的已采样进程和覆盖范围。
   打开选择器前冻结快照，离开界面仍停止采集；取消则丢弃待导出内容。配置变更可保留待导出快照，进程被系统回收后不恢复。
   文件写入在后台线程完成，不新增网络、存储或 root 权限。
